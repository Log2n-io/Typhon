# Known-red allowlist for the Nightly suppressed tier (#765 S0).
#
# WHAT THIS REPLACED. The tier's test step carried a bare `continue-on-error: true`, so the job reported success with any
# number of reds in it. That is the same defect the tier itself exists to remove — a signal nobody can act on — moved one
# level up: a red that cannot fail anything is indistinguishable from a green.
#
# HOW IT WORKS NOW. The test step still does not abort the job (a stress tier is a signal, not a merge gate), but a
# following BLOCKING step diffs the actual failures against this file:
#
#   * a failure NOT listed here  -> the job FAILS. This is the whole point: a new red is news.
#   * a listed test that PASSED  -> a warning in the step summary, not a failure. These fixtures are genuinely flaky, so
#                                   one green run is not proof the issue is fixed — but a name that stops appearing for
#                                   a week is your cue to delete the line and close the issue.
#
# RULES.
#   * Every line needs an issue. A name with no issue number is a suppression, and suppressions are what put this
#     subsystem 160 days behind its own defects.
#   * Match is on `ClassName.MethodName`, ignoring any parameterised suffix — one line covers all cases of a test.
#   * Adding a line is a deliberate act by a human who has read the failure. Do not add one to make a run green.
#   * Shrinking this file is the job. It should be empty.
